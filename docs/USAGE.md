## 截图与识别流程

工具栏、全局快捷键和托盘菜单发起截图时，可见的主窗口先最小化并隐藏，再进入框选；已隐藏到托盘的窗口保持隐藏，直接进入框选。普通识别和截图并翻译在框选完成后恢复主窗口，显示等待页与结果。

**静默识别**仍显示框选覆盖层，成功后自动复制原文，不进行翻译，也不自动弹出等待页或文字结果窗口。进度、取消与失败均不自动恢复主窗口；可通过托盘「主界面」或「设置」主动打开。静默仅作用于本次请求，下一次普通识别或翻译仍正常显示界面。启动参数 `--silent` 则表示启动后收起到托盘，与单次静默识别分别控制。

**框选样式**沿用旧版：1px 纯白边框，选区外保持原图一半亮度，选区内显示清晰原图。预览在离屏缓冲中完成合成，再一次提交到窗口，避免先显示暗层、后显示选区造成的闪烁；原始截图保持只读。

**任务控制**：处理期间不会重复排队；取消后立即恢复操作，保留已显示的文本，可马上开始新任务。后台识别进程及其网络连接会被终止，迟到结果不会覆盖新任务。

普通识别完成时恢复并将结果窗口移至普通窗口最前方，保留用户调整的尺寸、最大化状态和置顶选择；静默识别不自动打开窗口。

桌面界面专注截图与文字输入，不提供图片导入和拖放识别。文件识别可通过 MCP 的 `sightocr_ocr` 工具调用，支持 PNG、JPEG、BMP、WebP。

## 桌面界面

界面参考 Windows 11 截图工具：顶部紧凑工具栏、蓝色模式指示、浅色画布和居中快捷键提示。识别完成后先展示原文，继续翻译时在译文区域显示等待状态。保留系统标题栏、拖动、调整大小、最小化和最大化；标题栏随浅色/深色主题同步，也可选择跟随系统。

- **工具栏**：「新建」开始截图，旁边切换截图识别/截图并翻译模式；选择文字、表格、公式类型及本地/云端引擎。右侧图钉切换窗口置顶，齿轮直接打开设置。
- **原文 / 译文**：默认宽度使用紧凑分页，窗口加宽后可左右对照。语言选择、复制和翻译操作放在对应区域，文本可独立滚动，底部操作保持可见。原文和译文均可手动编辑：空白区点击后立即进入输入状态，清空文本后仍可继续输入；点击「翻译原文」提交。
- **设置**：按顺序包含常规、接口、快捷键、代理、关于五页。常规页包括应用主题、版面分析、开机自动启动和隐藏托盘图标；接口页通过服务选择器切换凭据与模型表单；关于页提供版本和配置位置。底部固定「保存」与「取消」按钮，外观与快捷键在保存成功后生效。「获取密钥」直接打开对应官方控制台。
- **任务反馈**：等待页显示当前阶段、提交任务时选定的服务与目标语言、已用时间和取消入口。截图并翻译会先展示识别原文，再等待译文。取消后忽略迟到的进度与完成事件；处理期间锁定输入，避免结果覆盖正在编辑的文字。

**文字显示与输入**：原文与译文使用 Windows 原生 Unicode 编辑控件，支持多语言字体回退、阿拉伯文/波斯文等双向排版、印度及东南亚文字连写和输入法；界面字体同时补齐各可选语言的系统字体回退。复制和翻译使用原始字符顺序。输入法组合期间保留临时文本和选区，选词提交后再更新正文格式。

**窗口尺寸**：客户区默认 740×680、最小 740×580 逻辑像素，可调整大小和最大化，未设置最大尺寸限制；150% 缩放下默认对应 1110×1020 物理像素。初始位置在当前显示器工作区居中，避开任务栏。

**动效**：按钮、切换、复制反馈、等待页等带有过渡动画，并遵循 Windows「显示动画」设置。

**图标资源**：程序/托盘图标使用 `assets/icon.ico`，窗口与关于页使用 `assets/icon.png`，截图光标使用 `assets/cursor/cross.png`。资源直接嵌入程序，发布后无需另外复制 assets 目录。

## 托盘与后台运行

托盘悬停提示仅显示「SightOCR」。托盘菜单按顺序包含「主界面、静默识别、截图识别、截图翻译、设置、重启、退出」七项。三项截图操作旁显示当前生效的快捷键；设置保存成功后同步更新。

- **关闭窗口**始终隐藏到后台，即使系统集成服务初始化失败也不退出；服务可用时全局快捷键继续响应，`--silent` 启动同样保持隐藏。
- **再次运行** SightOCR 会打开已有实例。
- **「隐藏托盘图标」**仅控制图标显示，不影响后台运行。
- **「重启」**先释放窗口、任务与热键，再启动新进程；**「退出」**明确结束进程并释放资源。

## 快捷键设置

在「设置 → 快捷键」按顺序录入静默识别、截图识别、截图翻译三项快捷键。点击对应控件后直接按下单键或组合键，无需手动输入 `Ctrl+F4` 等文字。

- 三项不能使用相同的按键组合。
- 录入结果先保留在设置草稿中，保存成功后才生效；取消设置或保存失败时保持原快捷键。
- 被其他程序占用导致的注册冲突需在设置中调整。

## 识别引擎

默认使用本地 OneOCR，截图只在内存中处理。可选百度、腾讯或自定义的[模型接口](#模型接口)进行云端文字、表格或公式识别。

| 识别类型 | 本地 OneOCR | 云端 |
| --- | --- | --- |
| 文字 | ✅ | ✅ |
| 表格 | ✅ 输出 TSV，可直接粘贴到 Excel | ✅ |
| 公式 | ❌ | ✅ 输出 LaTeX |

- 本地引擎不支持公式：其文字模型没有数学符号（∫、√、Σ 等会被误读），上下标与分式结构也会丢失。
- 云端 OCR 失败时显示原因并回退本地，保留接口选择；公式回退只能获得普通文字。
- 公式结果统一为 LaTeX 显示块：每个公式用独立行的 `\[` 和 `\]` 包裹，多公式之间保留空行，便于复制到支持 LaTeX 的编辑器。

## 本地表格识别

本地表格结合自适应局部对比度、多尺度水平/垂直线检测与文字位置推断，改善浅色、短线、断线和部分边框表格的行列还原，并保留空白内列。

- **深色与斑马纹**：深色主题表格会先统一明暗再检测线条；斑马纹等只覆盖部分宽度的色块边缘不再被当作单元格边框。
- **单元格文字**：中文、日文单元格内换行与字间空格直接拼接，英文、韩文保留词间空格。
- **外框与周边文字**：只有外框的表格会继续按文字行分组。有外框的表格，框外标题与备注各自单独成行，页码会被忽略。
- **斜线表头**：左上角斜线表头读作「星期/科目/时间」一个单元格。
- **倾斜与透视**：轻微倾斜（4° 以内）的手机拍摄或扫描表格会先按线条与文字行的投影测得角度并拉正；斜拍照片的左右边框呈梯形时，按各条通栏横线的两端拟合左右边框并逐行做梯形校正。
- **边框缺失**：模糊照片丢失外侧边框时，以贯穿上下边框的内部竖线判定表格范围；竖排的「上午 / 下午」等合并标签与右侧内容之间的空白通道也作为列边界。
- **鲁棒性**：JPEG 压缩、模糊、灰度、0.6–2 倍缩放下正文结构保持一致。

强烈透视或弯曲的照片、看不清的斜线表头及复杂合并单元格仍需校对。

## 版面分析

「设置 → 常规 → 版面分析」（原「合并文本换行」，设置自动沿用）开启后，文字识别按「识别行与坐标 → 版面分析 → 段落合并 → 输出」处理：

1. 按文字行坐标切分出阅读顺序的文本块：双栏先左后右，通栏标题在上；同行排列的「标签　内容」表单不拆成两栏。
2. 在块内把因宽度换行的行合并为段落；遇到段间距、字号变化、未写满的短行、首行缩进或列表标记（`1.`、`(1)`、`一、`、`•`、`第X条` 等）时另起段落。导航菜单等窄块逐行保留。
3. 每个段落输出为一行，中文、日文直接拼接，英文保留空格。

倾斜截图会先按测得的角度校正文字框坐标。云端识别没有坐标，按空行、列表标记、短行和句末标点做纯文本段落合并；表格与公式不受影响。

## 翻译服务

翻译支持 Bing、百度、腾讯和可翻译的模型接口；Mistral OCR 协议仅用于识别。相同源/目标语言时保持原文。

- **Bing**（默认）：使用微软网页翻译的兼容接口，无需密钥；授权页可在可信 Bing HTTPS 站点间进行地区跳转，并保持对应站点的会话。网页接口的可用性取决于服务方。
- **百度、腾讯**：在「设置 → 接口」中各自的凭据卡片填写密钥。
- **模型接口**：见下节。

云端服务需要网络及对应权限/配额。

## 模型接口

百度、腾讯以外的 AI 服务统一为「模型接口」，可添加多个，每个接口有独立的名称、协议、地址、密钥、识别模型和翻译模型。

在「设置 → 接口」的服务下拉菜单中选择「＋ 添加模型接口」。「快速填入」可一键填入常见服务商的协议、地址、默认模型和建议名称（不会填入密钥）；**名称可随意修改**，并显示在工具栏引擎菜单与译文服务菜单中。识别模型或翻译模型留空的一项不会出现在对应菜单中。

| 协议 | 请求地址 | 认证方式 | 适用 |
| --- | --- | --- | --- |
| OpenAI Chat Completions 兼容 | `{Base URL}/chat/completions` | `Authorization: Bearer` | OpenAI、Azure OpenAI（v1）、NVIDIA、腾讯混元、DeepSeek、通义千问、豆包、智谱 GLM、Kimi、硅基流动、OpenRouter、Ollama、LM Studio、vLLM 等 |
| OpenAI Responses | `{Base URL}/responses` | `Authorization: Bearer` | OpenAI、Azure OpenAI（v1） |
| Anthropic Messages | `{Base URL}/messages` | `x-api-key` + `anthropic-version: 2026-10-21` | Claude 及 Anthropic 兼容网关 |
| Google Gemini | `{Base URL}/models/{模型}:generateContent` | `x-goog-api-key` | Gemini API |
| Mistral OCR | `{Base URL}/ocr` | `Authorization: Bearer` | Mistral 文档 OCR（仅识别） |

Base URL 应填写包含版本路径的地址，例如 `https://api.example.com/v1`，无需追加 `/chat/completions` 或 `/ocr`。

- 服务商差异按地址自动处理：OpenAI 与 Azure OpenAI 使用 `max_completion_tokens` 和高精度图片，Azure 另附 `api-key` 头（Base URL 形如 `https://资源名.openai.azure.com/openai/v1`）；NVIDIA 支持其 202 异步轮询。
- 远程服务必须使用 HTTPS；本机服务（`localhost`、`127.0.0.1`、`::1`）可使用 HTTP，且可不填密钥。本机请求不经过代理。
- 设置页实时显示将要请求的完整地址；「测试翻译」（或仅识别接口的「测试识别」）用当前填写内容发起一次很小的调用，验证地址、密钥与模型。
- 图片与文字只放在用户消息中并按不可信内容处理，不启用工具调用，不跟随重定向，失败时不切换到其他服务；截断、拒绝、仅含推理内容等结果一律视为失败。
- 升级时，已填写密钥或正在使用的 Mistral、OpenAI、NVIDIA 与 2.1 早期的「通用模型」设置自动转为同名模型接口，当前选择随之保留；旧字段不再重复保存密钥。
- MCP 的 `sightocr_translate` 使用 `provider: "model:<编号>"` 调用模型接口；`openai`、`nvidia`、`generic` 旧名称继续可用。

协议参考：[Mistral OCR](https://docs.mistral.ai/api/endpoint/ocr) · [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat) · [OpenAI Responses](https://developers.openai.com/api/reference/resources/responses) · [Anthropic Messages](https://platform.claude.com/docs/en/api/messages) · [Gemini generateContent](https://ai.google.dev/api/generate-content) · [NVIDIA Qwen3.5](https://docs.api.nvidia.com/nim/reference/qwen-qwen3-5-122b-a10b-infer)

### 真实服务验收

在项目根目录 `.env` 中写入 `{前缀}_BASE_URL`、`{前缀}_API_KEY`、`{前缀}_OCR_MODEL`、`{前缀}_TRANSLATE_MODEL`（前缀为 `TENCENT`、`MISTRAL`、`AZURE_OPENAI`），然后运行：

```powershell
cargo test --test live_models -- --ignored --nocapture
```

该测试会发送示例表格图片、公式图片与一句英文并消耗少量额度，不打印密钥；`.env` 已列入 `.gitignore`。

## 代理

在「设置 → 代理」选择连接方式，默认跟随系统：

| 模式 | 行为 |
| --- | --- |
| 跟随系统 | 每次新任务前检查代理环境变量与 Windows 手动代理设置，变化时刷新连接与服务会话，无需重启。环境变量优先；不执行 PAC 脚本或 WPAD 自动发现。 |
| 不使用代理 | SightOCR 直接连接云端服务。 |
| 手动代理 | 使用指定的 HTTP、HTTPS、SOCKS5 或 SOCKS5H 代理，例如 `http://127.0.0.1:7890`。 |

代理认证的用户名和密码分别填写，密码默认遮罩；无需认证时留空。切换到系统或直连模式后，手动字段禁用并保留已填内容。该设置仅作用于 SightOCR 的云端识别、翻译与软件更新，不修改 Windows 或其他应用的代理设置；保存后对新任务生效，本地 OCR 无需网络。

## 配置文件

- 默认保存到 `%APPDATA%\SightOCR\config.json`，避免安装目录写入权限问题。
- 首次运行导入程序/源码目录的旧 `config.json`，兼容 `paths.json` 的 `config_dir`；保留未知字段，原文件不改动。
- 兼容旧版语言显示名和 `last_source_lang` / `last_target_lang`。
- 旧配置缺少静默快捷键时自动补齐：普通识别为旧默认 F4、且翻译未占用 F5 时，将普通识别改为 F5，静默识别使用 F4。其他原有识别/翻译组合优先保留；若 F4 已被这两项占用，新静默键从 F6 至 F24 依次选择不重复的按键。已经保存的三项快捷键不会再次重置。
- 同目录临时写入、同步并原子替换；损坏配置不会被默认值覆盖，需修复后重启。
- 服务密钥和代理认证保存在本机 JSON，密码与密钥在界面掩码显示，不输出到日志；**并非加密凭据库**。

| 环境变量 | 作用 |
| --- | --- |
| `SIGHTOCR_CONFIG` | 指定独立配置文件，并跳过旧配置迁移 |
| `SIGHTOCR_RESOURCES` | 指定包含 OneOCR DLL/模型的目录 |

## 软件更新

程序默认每天在后台检查一次 GitHub 正式版本（「设置 → 常规 → 自动检查更新」可关闭），也可在「设置 → 关于 → 软件更新」手动检查。

- 发现新版本时工具栏显示「新版本」标记，不会自动下载；可查看版本说明后选择「下载并安装」或「跳过此版本」。
- 下载可取消，完成后验证大小和 SHA256，再由你选择「立即重启并安装」或「退出 SightOCR 时自动安装」；更新沿用已保存的网络代理设置。
- 安装包只接受本项目对应版本的 `SightOCR-Setup-版本号.exe`，缺少有效校验信息时不执行安装。发布新版本时应同时上传 `SHA256SUMS.txt`。
- 覆盖安装沿用原安装目录、直接覆盖文件并保留快捷方式与设置；遇到目标目录内正在运行的程序会提示确认，确定后自动关闭并继续安装。
- 卸载时可选择是否同时删除设置与密钥，默认保留。

安装、升级、静默参数与卸载的完整说明见 [Windows 安装包](INSTALLATION.md)。

## 隐私与临时文件

- 截图仅在内存和匿名管道中传递，识别后不会留下临时截图文件。
- 本地 OCR 不联网；云端识别与翻译只把内容发送给你选择的服务。
- 程序启动时及每 24 小时检查旧版缓存：仅删除 `%TEMP%\SightOCR\screenshots` 和 `%TEMP%` 中命名为 `sight_YYYYMMDD_HHMMSS.png`、超过 72 小时的文件，不递归删除目录，不删除用户导入或保存的图片。
